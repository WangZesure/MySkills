# Point Research（点调研）：已有 idea → 找最接近的论文

## 方法总览

把 idea 拆成若干"约束组件"，从最严格的组合（与 idea 完全一致的表述）开始检索，
**逐步放宽限制**，直到找到相关论文或确认空白。核心原则：**先精后泛，记录断档**。

## 流程

1. **形式化 idea**：一句话定义 + 列出关键组件（输入 / 输出 / 结构 / 损失 / 应用域）。
2. **分层（由近到远）**：
   - Layer 1：所有组件全保留的精确查询（用带引号词组）
   - Layer 2：去掉一个次要组件（如损失项、域）
   - Layer 3：只保留核心机制（如"加子网络""低秩调制"）
   - Layer 4：只保留主题（如"条件忠实度"）
3. **每层检索**：用 `scripts/arxiv_search.py`（含代理 + 429 限流退避）。
4. **验证命中**：抓摘要确认机制真相关；查代码可用性（GitHub API / gh_grep）。
5. **输出**：分层报告表（每层论文 + 与 idea 的差异）+ **空白定位**（哪一层断档 = 新颖点）。

## 查询构建要点

- arXiv API 语法：`all:"词组"` 组合 AND/OR；标题精确匹配 `ti:"标题"`；
  排序 `sortBy=submittedDate&sortOrder=descending`。
- 无结果时按顺序放宽：去掉引号 → 换同义词 → 只留核心机制 → 只留应用域。
- 429 限流：指数退避（15s×attempt，最多 5 次），查询串行、间隔 20s+。
- 代理：查询脚本默认走 `http://127.0.0.1:7890`（无代理时置空）。

## 代码可用性验证

- GitHub API：`https://api.github.com/search/repositories?q=关键词`（需 UA；需代理）。
- `gh_grep_searchGitHub`：搜特征代码模式（如 `class DiffusionAutoencoder`）确认实现真实存在。
- 报告中区分"本轮实证过"与"凭已有知识引用，编号待核"。

## 输出模板

```markdown
## 调研报告：<idea 一句话>
### Layer 1（最接近）… 表格：论文 | arXiv | 与 idea 的距离 | 要点
### Layer 2/3/4 …
### 空白定位：我们的做法 = <最近骨架> + <我们的组件A> + <我们的组件B>，文献没有 <A+B 组合>
```
